CASE STUDY / 01 · NEW PORTFOLIO DEMO

Trust is a pipeline feature.

The challenge: turn out-of-order customer changes into a consistent current-state dataset without allowing a stale replay to undo a deletion.

Architecture & decisions

Configuration defines the input, storage root, key, source sequence, and allowed operations. Bronze captures the input snapshot. Invalid keys, sequences, and operations go to quarantine. Silver applies the latest change per key with Delta MERGE; Gold summarizes active customers by region.

Delete tombstones preserve source sequence. Only newer events update existing keys, and conflicting payloads at the same version fail the run instead of producing an arbitrary result.

What to inspect

  • Six synthetic events, including an update, a delete, and a rejected key.
  • Expected result: two active customers and one quarantined event.
  • Integration test checks repeatability and stale replay after deletion.
  • Delta tables plus a JSON quality report.

Scope & tradeoffs

Local synthetic demo; no production throughput claim. Bronze is a replaceable snapshot. Production source cursors, schema evolution, orchestration, security, and scale validation require further work.

CASE STUDY / 02 · NEW PORTFOLIO DEMO

Know what enters your reports.

The challenge: distinguish usable transactions from duplicates and invalid records while keeping streaming state bounded.

Architecture & decisions

Kafka JSON events enter Spark Structured Streaming. An audit sink keeps parsed inputs. A ten-minute event-time watermark bounds transaction-ID deduplication. Quality rules check required IDs, timestamps, positive finite amounts, and USD currency.

Each retained batch writes quality rows, JSON metrics, and valid-only Parquet for reporting. Separate checkpoint locations maintain each query’s progress.

What to inspect

  • Synthetic duplicate, negative amount, and deliberately late event.
  • File input mode for a broker-free introduction.
  • Kafka producer with spaced events to exercise watermark advancement.
  • Spark progress exposes watermark and state metrics.

Scope & tradeoffs

Deduplication is bounded by retained state. Very late events may be dropped; the audit supports a future correction workflow. Batch outputs are replayable but not atomically committed across sinks. This is a quality monitor, not a fraud detector.
